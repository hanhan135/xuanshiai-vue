# 服务红娘管理中心框架开发文档

## 1. 定位与范围

服务红娘管理中心是“我要做红娘”流程中的受限工作台，不新增一级 Tab，也不是面向所有运营人员的全局后台。本期交付首页框架、资料待审的前端工作流入口，以及明确的服务端接口边界；尚未接入的数据不能被当作真实运营数据。

## 2. 进入门槛

进入管理中心前，客户端会请求 `GET /matchmaker/management-center/access`。服务端返回的 `can_access`、角色状态和订单状态需要同时成立：账号状态为 `active`，付款状态为 `paid`，且服务端明确允许访问。客户端检查只用于减少误入，不能替代服务端授权。

未付款时页面只展示服务开通引导；账号未激活、订单状态不正确或服务端拒绝时，均不得展示管理中心业务数据。

## 3. 首页框架

首页包含欢迎区、8 项门店数据简报、5 个快捷入口、专属推广工具、10 个功能入口和退出登录。数据简报由 `GET /matchmaker/management-center/dashboard` 提供；未接入的指标统一保持 `--`，不推测订单、会员、审核、分成或财务数据。

当前看板不展示 Mock 用户、联系方式、真实会员资料、金额、数量或审核明细，也不以本地样例填充数据看板。资料待审是与看板分开的前端 Mock 工作流，用于演示审核、弃海、捞取、联系、跟进、复制、编辑、匹配、红娘说、改红娘、录入和筛选；其中资料与写入仅保留在前端 Mock，真实资料、联系方式授权和写入必须等待对应服务端接口。

## 4. 数据与权限边界

真实管理中心必须实施服务端 RBAC：按红娘岗位、门店、所属会员、业务动作和数据字段分别校验，并在审核、编辑、弃海、捞取、联系、牵线、约见、分成和导出等敏感操作中记录审计日志。

管理中心不能绕过用户的申请认识、双方同意、聊天和联系方式保护规则。红娘可以协助梳理与推进，但不能代表用户同意认识、开启聊天或交换联系方式。

## 5. 当前开发开关与后续接口

`MATCHMAKER_MANAGEMENT_CENTER_USE_MOCK` 仅返回无明细的数据骨架，方便验证布局与错误状态；测试服完成访问状态和看板接口后应关闭该开关。真实接口至少需要保证：

- 访问状态由服务端计算并返回岗位、付款和允许范围；
- 看板不含手机号、微信号等敏感字段；
- 每个明细或写操作使用独立的服务端 RBAC 与审计；
- 前端把未知或异常响应当作无权限或加载失败处理，不能降级展示本地个人资料。
